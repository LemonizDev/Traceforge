# Workflow 09: Intelligence and Insights Generation

## Goal
Explain the repository's purpose, architecture, capabilities, strengths, limitations, and opportunities.

## Steps
1. Summarize repository identity and intended purpose from source evidence.
2. Describe architecture, component inventory, workflows, and dependency patterns.
3. Assess complexity and coverage using measurable graph and inventory metrics.
4. Synthesize security, extraction, environment, and execution findings.
5. Generate strengths, limitations, risks, and improvement recommendations.
6. Label facts, interpretations, and hypotheses separately.
7. Attach evidence and confidence to substantive claims.

## Outputs
Repository intelligence report, capability map, complexity indicators, recommendations, unresolved questions.

## Acceptance criteria
- Recommendations are not presented as facts.
- Metrics define their calculation and scope.
- Model-generated claims without evidence remain hypotheses.
